# NK-09 道路冠水想定箇所: PDF から座標を起こす試行（山梨・2026-10-02）

## 前提
- 座標付きの公式配布は無い（ハザードマップポータルのオープンデータ一覧 2026-08-28 更新版に無い。2026-10-02 再確認）。
  利用者が確認したとおり、各道路管理者の PDF がばらばらにあるだけ
- ★利用者の要求: 「LLM が間違えるなら人間が見ても信用できない」→ **LLM の出力を信用せず、各段を機械で検査する**

## 対象
甲府河川国道事務所「山梨県内の道路冠水注意箇所」（令和6年8月1日時点・18箇所）
- 一覧 https://www.ktr.mlit.go.jp/ktr_content/content/000889857.pdf
- 詳細図 https://www.ktr.mlit.go.jp/ktr_content/content/000889858.pdf （1箇所1ページ・地理院地図に赤丸）
- 管理者の内訳: 国 2 / 山梨県 7 / 市町 9

## 方法（`preprocess/tools/nk09_pilot/`）
| 段 | 何で | LLM | 検査 |
|---|---|---|---|
| 1 転記 | PDF の **text layer** を項目に分ける | ★分けるだけ（Claude） | 連結が text layer と**完全一致**するか（自動） |
| 2 赤丸の検出 | ページを描画し、赤の輪を色で検出 | 使わない | 1ページに丸が**ちょうど1つ**か |
| 3 位置 | 詳細図の画像を**地理院タイル（標準地図 z17）に画像照合**（縁の相関・複数縮尺）。探す範囲は地先名の代表点の周り 1.6km | 使わない・OSM も使わない | 1位と2位の一致度の差（1位 ≥0.4 かつ差 ≥0.2 で確定） |
| 4 突き合わせ | 全国版が OSM の幾何から検出したアンダーパス（T-01）との距離 | 使わない | 独立な2つの方法が一致するか |

★地理院タイルの取得はプロジェクトの TileFetcher（逐次・キャッシュ・UA）

## 結果
| | 件数 |
|---|---:|
| 転記が text layer と完全一致 | **18/18** |
| 赤丸がちょうど1つ | **18/18** |
| 画像照合で位置が確定 | **16/18**（No.5・No.12 は一致度の差が小さく**自動で「未確定」に落ちた**） |
| 確定した点が道路の上（8m 以内） | **16/16** |
| OSM で検出したアンダーパスと 50m 以内で一致 | **12/16** |
| 一致しない4件（No.1・9・13・15） | 並べて見ると**4件とも画像の側が正しく、OSM の検出が漏れていた**（3件は検出なし、1件は 213m ずれ）→ `NK-09_試行_山梨_不一致4件.png` |

★**読み取れたこと**
- 位置は LLM ではなく画像照合で決まり、**失敗は黙らずに「未確定」として出る**（2件）
- ★**公式の箇所の 4/16（25%）は、全国版のアンダーパス検出（T-01 の幾何推定）で拾えていない。**
  このデータを入れる価値は「既知の冠水箇所」の表示だけでなく、**判定不能の漏れを埋める**ことにもある
- 不一致4件の判定だけは目視（LLM）。ただし「画像の地図の記号（標高点 867 等）が同じ位置に来ている」ことを根拠にしている

## 残ること
- **形式の違う PDF で試す**（詳細図の無いもの・スキャン・一覧だけ）。この PDF は1箇所1ページ・地理院地図という最も起こしやすい形
- 未確定2件の扱い（地先名から引けない・JPEG の画質）
- **利用条件**: 1つの PDF に国・県・市町の箇所が混ざる。国（関東地方整備局）以外の条件は未確認
- 全国の件数・PDF の数は未確認

# 試行2: 東京都（2026-10-02）— 起こしにくい形

東京国道事務所・相武国道事務所 記者発表「東京都内のアンダーパス部の冠水注意箇所は135箇所」（平成29年8月4日）
https://www.ktr.mlit.go.jp/ktr_content/content/000725521.pdf
★**2017年の資料。** 現在も有効かは未確認（山梨は令和6年時点）

## 山梨との違い
- 一覧（4・5ページ）は**スキャン画像で text layer が無い** → 転記の検査に PDF の文字を使えない
- **詳細図が無い。** 都内全域を1枚に描いた地図に番号付きの印があるだけ（印1つが数十m〜）
- 管理者: 国 24 / 都 63 / 区 26 / 市 20 / 臨港道路 1 / 区有通路 1

## 方法（`preprocess/tools/nk09_pilot/tokyo/`）
| 段 | 何で | 検査 |
|---|---|---|
| 1 転記 | **2つの独立した読み手**: Claude（画像を読む）と macOS Vision の OCR（`ocr.swift`。機械） | 2つが一致するか。不一致はスキャンを切り出して判定 |
| 2 地図の印 | 色で検出（赤・青・緑・桃＝凡例の4区分）。番号は地図を拡大して Vision で OCR | 番号のそばに、凡例どおりの色の印があるか |
| 3 候補 | 行の文字から OSM の候補（構造物名・路線番号の立体交差/トンネル・地先の町丁目の近く）。市区町村の範囲に限る | — |
| 4 位置 | 地図を印で**地理参照**（アフィン・反復）し、各行の印に最も近い候補を採る | 残差。★**行と印の対応を入れ替えた帰無検査**で偶然の一致率を測る |

## 結果
| | 件数 |
|---|---:|
| 転記: 2つの読み手が3項目とも一致 | **117/135** → Claude の誤りを直して 119/135 |
| ★**Claude の転記の誤り** | **2件**（No.41 路線番号を上の行から写した / No.124 桜横町を桜橋町）。**2つの読み手の突き合わせで2件とも見つかった** |
| Vision の誤り | 18件（浦田・瑞穗・ハッ山・隋道 など）。いずれも Claude 側が正しかった |
| 地図の番号の読み取り | 135/135。凡例どおりの色の印のそば（66px 以内）が 133/135 |
| 位置: 地図の印と OSM 候補が **200m 以内で一致** | **109/131**（83%） |
| 　帰無検査（対応を入れ替え）での 200m 以内の一致 | **1.8%**（偶然では説明できない） |
| 要確認（200〜800m） | 17 |
| 不一致（800m 以上）・候補なし | 5 ＋ 4 |
| 種別ごとの確定 | 国道 20/24・都道 54/63・区道 22/26・市道 13/20・臨港/区有 0/2 |

★**読み取れたこと**
- **転記は LLM 単独では信用できない**（405 項目中 2 件誤り＝0.5%）。ただし**独立な機械の読み手と突き合わせれば見つかる**
- 位置の精度は**地図の縮尺で頭打ち**（残差 中央値 73m）。確定した点は OSM の構造物（立体交差・トンネル）そのものなので
  点自体は正確だが、**近接する別の立体交差を選んでいる可能性**は残る（2つが 100m 以内に並ぶ所）
- 崩れるのは: 番号の読み違い（No.1 は 10km 先の印を拾った）・OSM に構造物が無い／名前が違う所（市道・区有通路・架道橋）・
  隣り合う構造物（No.28 胡録トンネル→隣の瑞光トンネル）
- ★**2017年の資料**であり、現在の公表と一致するかは別途確認が要る

# 位置不明を説明表の文字から推す試み（2026-10-09）— ★採らなかった

位置不明 541 件（北陸 174・東北 151・中部 99・関東 96・沖縄 13 ほか）を、説明表の文字（市区町村・字丁目・路線・施設名）と
OSM の道路の名前・路線番号・立体交差の下で推せないか試した（`preprocess/tools/nk09_name/locate_by_name.py`。LLM・画像照合なし）。
★整備局が座標を公表している 3,589 か所で、座標を隠して同じ手順で推し、答え合わせをした。

| | 推せた | 円（半径 150〜400m）に入った |
|---|---:|---:|
| 答え合わせ | 177（4.9%） | 128（72.3%） |
| ★帰無検査（路線・施設名を同じ都道府県の別の箇所と入れ替え） | 19（0.5%） | 1（5.3%） |
| 字丁目の代表点から 500m 以内に限る | 99（2.8%） | 88（89%） |

- ★**位置不明 541 件に当てると、要確認にできるのは 6 件だけ**（500m の条件つき）→ 採らない（CSV は変えていない）
- 推せない主な理由: 路線・施設名が OSM の道路に無い 299（市町村道の名前・「◯◯ガード」「◯◯地下道」は OSM にまず無い）、
  当たりが長い道路に沿って広がる 80（同じ路線に立体交差の下が複数ある）、沖縄は国道の番号が書かれていない
- 道具の直し: 北陸の様式（「道路名国道8号」「施設名◯◯」を1行に書く）は `parse_one` が住所・警察署を拾っていた → 道具の側で上書き
