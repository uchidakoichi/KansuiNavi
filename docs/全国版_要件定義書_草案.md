## 1. 背景・目的

### 1.1 藤沢版 PoC で分かったこと

| 項目 | 結果（実測） |
|---|---|
| 目的① 公開データだけで道路単位の冠水リスクを出せるか | **成立**。市の雨水出水浸水想定区域に対し AUC **0.720** / AP **0.373**（陽性率 0.142）。中程度 |
| 目的② リスク回避経路は実用的な迂回か | **合格**。ハード制約（アンダーパス除外）で 289/292 が最速比 2.0 以内 |
| アンダーパスの幾何検出 | 適合率 **96.7%**（120地点中116） |
| 「水が溜まる形か」の目視判別 | ★**判別できなかった**（同一判定者で12.1%→34.8%と食い違い） |
| 道路幅員 | PLATEAU の道路面から実測。市域内エッジの **94.0%** で測れた |

★AUC 0.72 は「上位2割を危険としても想定区域の地点の 44.6% しか拾えない」水準である。
全国版でもこの実力を前提にし、誇張しない。

### 1.2 全国版の目的 ── **一般の運転者向け**（NK-01 決定 2026-09-19）

検討した候補と、選ばれたもの（**(b)**）:

| 候補 | 何のため | 要件への影響 |
|---|---|---|
| (a) 方法の汎用性の検証 | 藤沢で通用した方法が他地域でも通用するか確かめる（研究的） | 地域別の検証が中心。公開範囲は狭くてよい |
| (b) 一般利用者向けサービス | 全国の運転者が使う | 可用性・法務・問い合わせ対応・運用主体が必要。PoC の枠を超える |
| (c) 自治体職員向け業務ツール | 各自治体の消防・道路・危機管理が使う | 自治体ごとの公開範囲・データ提供の調整が要る |

藤沢版は明示的に「災害時の実運用、市民への公式な避難誘導、リアルタイム通行止め情報の提供」を
目的に含めなかった。全国版でこの線引きを変えるかどうかも NK-01 に含む。

### 1.3 ★藤沢版から変更した絶対ルール（2026-09-20・利用者判断）

藤沢版 CLAUDE.md の「絶対に守るルール」のうち **2つを全国版では変更する。**
★藤沢版（`../Kansui`）のルールは変更しない。あちらはそのまま。

| 藤沢版のルール | 全国版での扱い | 利用者の判断 |
|---|---|---|
| **1. 有償サービス・従量課金を導入しない。月額0円が必須** | ★**PoC 期間中のみ月額0円。PoC 後は費用がかかる方式も検討する** | 「無料にこだわり機能を制限することは避けたい」。費用面は PoC 後に検討 |
| **6. 位置情報をサーバへ送信・保存しない** | ★**外部に渡ることを許容する**（出発地・目的地・入力した住所） | 一般に使ってもらうために受け入れる |

変更していないルール: 2（標高 API 禁止）／3（タイル取得のマナー）／4（パラメータの外出し）／
5（「安全」と書かない）／7（出典表示）／8（免責同意）／9（アクセス解析を入れない）／10（推測で埋めない）。

★**ルール9（アクセス解析を入れない）は据え置き。** 位置情報の外部送信を許容したことと
アクセス解析を入れるかは別の論点なので、変えるなら別途決める（NK-13）。

### 1.4 ★ルール変更から生じる要件

1. ★**個人情報の取扱いの明示が必要になる。**
   位置情報（出発地・目的地・入力した住所）が外部へ渡るなら、一般公開・個人運用では
   **プライバシーポリシーの掲示**が要る。何を・どこへ・何のために送り・どれだけ保持するかを書く。
   - ★藤沢版のガイドの「位置情報は送信していません」「サーバがありません」は**そのまま使えない**。
2. **PoC 期間中は無料枠に収め、「超えたら止める」も維持する**（止まっても PoC だから）。
   ★ただし**一般公開後に「豪雨時に止まる」ことは許されない**ので、PoC を出る前に費用方針を決める。
3. **実行時に外部サービスを呼ぶ設計が選べるようになった。** 採否は機能ごとに判断する。
   ★ただし**経路探索そのものは外部化できない** —— 自前のリスク重み（Δh・幅員）を
   外部の経路 API に渡せないため（§5）。

## 2. 設計思想（藤沢版から継承するもの）

全国版でも変えない。

1. **「標高が低い場所」≠「冠水する場所」。** 中核指標は近傍最小標高との差 Δh。
2. **根拠の性質で3つに分ける。** 地形推定（推定）／アンダーパス（事実）／冠水注意箇所（実績）。
   1つの尺度に混ぜない。
3. **「わからない」を「大丈夫」に丸めない。** アンダーパスは判定不能として4段階の外に置く。
4. **推測で埋めない。** 測れない所は NaN（不明）のまま扱う。
5. **誇張しない。** 当たり具合は地域ごとに実測した値だけを言う。

★ただし藤沢版のもう一つの柱「**サーバを持たず、ブラウザ内で完結する**」は、
全国規模でそのまま維持できるかが §3 の中心的な論点になる。

## 3. 全国化で変わるところ（★この草案の中心）

### 3.1 規模

| | 藤沢版（実測） | 全国版（概算） |
|---|---|---|
| 対象面積 | 69.56 km²（＋周辺3km） | 約38万 km²（面積比 約5,400倍）※全国面積は概数・出典要確認 |
| 道路グラフ | エッジ 177,542本 ／ `graph.bin` 4.6 MB（gzip 2.1 MB） | **1 GB を超える見込み** |
| 標高タイル（DEM5A・z15） | 335枚 | **数十万枚規模**（z15 は北緯35度で約1km四方） |
| 冠水注意箇所 | 13か所（手で座標付け） | 地方整備局等ごとに数百か所規模（未確認） |

道路グラフは面積比で広げると数十GB、道路延長の比で広げると 1GB 強になる。
道路密度の地域差が大きいので幅があるが、**どちらでも §3.2 の結論は変わらない。**

### 3.2 道路グラフ ── 1ファイルで配れない。地域分割が必須

- Cloudflare Pages（Free）は **1ファイル 25 MiB まで**、**1サイト 20,000 ファイルまで**
  （公式、2026年9月5日更新）。全国のグラフは1ファイルに収まらない。
- そもそも 1GB 超をブラウザに丸ごと読ませられない。
- → **地域ごとに分割し、見ている範囲・経路に要る範囲だけ読む**設計に変える。

未確定のまま残る論点:

- **分割の単位**（2次メッシュ＝約10km四方 など）と、それによる**ファイル数**（NK-06）。
  藤沢版は自前配信フォントだけで既に **379ファイル**使っている。
- **分割の境界をまたぐ経路**の扱い。近距離なら周辺の区画をまとめて読めばよいが、
  長距離（県をまたぐ等）を対象にするかどうか（NK-06）。
- **性能要件**。藤沢版は「市域内の任意2点で3秒以内」だった。全国版は
  「◯km 以内の2点で◯秒以内」のように**距離で範囲を切る必要がある**（NK-06）。

### 3.3 標高 ── ★実行時にブラウザが取る（案B。2026-09-20 採用）

★**採用: 案B。** 利用者のブラウザが、経路に必要な範囲の標高タイルだけを取り、Δh をその場で計算する。
→ **標高の一括ダウンロードは不要になる。** 論点と測るべきことは `docs/調査_API・MCP・既存プロジェクト.md` §8。

以下は、なぜ前処理での一括取得（案A）を採らなかったかの記録。

藤沢版は地理院の標高タイルを**逐次・1秒間隔**で取った（絶対ルール3）。
全国で同じことをすると数十万枚を数日かけて取ることになり、**国土地理院のサーバに長時間当て続ける。**

候補として、国土地理院の**基盤地図情報ダウンロードサービス**（数値標高モデル）がある。

| 確認できたこと（2026-09-19） | 内容 |
|---|---|
| メッシュの種類 | 1m ／ 5m ／ 10m |
| 形式 | JPGIS（GML） |
| ダウンロード単位 | 1m は3次メッシュ、10m は2次メッシュ。5m は**記載なし** |
| ★利用者登録 | **必要**（「ダウンロード実行の際には、IDとパスワードの入力が必要です」） |
| 一括ダウンロードの上限 | **記載なし** |
| 利用規約・出典表示 | 別ページ。**未確認** |

★**ログインが要るため、この取得は利用者ご本人に行っていただく工程になる。**
（開発側が代わりに認証して取ることはしない。）

★**DEM10B の区画は Δh の分解能が足りず、リスク算出の対象外になる**（藤沢版 T-07）。
藤沢市は DEM5A が 98.98% だったが、**全国の DEM5A 被覆率は測っていない**（NK-07）。
山間部を中心に、**広い範囲が「対象外」になる可能性がある。**

### 3.4 座標系 ── 19系に分かれる

- 藤沢版は距離の計算をすべて**平面直角座標系 IX系（EPSG:6677）**で行った（T-05）。
- 全国では平面直角座標系が **I〜XIX の19系**に分かれている
  （平成14年国土交通省告示第9号。JGD2011 では EPSG:6669〜6687）。
- → Δh の半径（100m／250m）・幅員の断面・起終点の寄せ距離など、**距離を扱う計算はすべて
  その地域の系で行う**必要がある。IX系のまま全国で計算すると、IX系から遠い地域ほど歪む。
- ★**系の境界をまたぐ区画・道路**の扱い（NK-08）。
  1つの都道府県が複数の系にまたがる場合があるかは、告示の適用区域で要確認。

### 3.5 ハザード情報（重ねて表示）

| 種類 | 全国での状況 |
|---|---|
| 洪水（想定最大規模）・高潮 | ハザードマップポータルのタイルで全国を配信。★藤沢版は**都道府県別レイヤ**（URL の `/14/` が神奈川県）を使っていた。全国の合成レイヤの有無と凡例は要確認（NK-14） |
| 内水 | ★**配信は一部の市町村のみ**（藤沢版の調査時点 2026-08 で62市町村。神奈川県内は3市）。全国の大半は無い |
| 内水（PLATEAU） | PLATEAU の整備都市のうち、内水モデルを持つ都市だけ |
| 土砂災害 | PLATEAU の整備都市のみで確認済み。全国の取得経路は未確認 |

★**藤沢版で分かった注意**: 内水の「PDF をジオリファレンスしたラスタ」は、市が持つベクタ版と比べて
指定区域の **76.3% を取りこぼしていた**。全国版で他都市の PDF を同じ方法で起こすことはしない。

### 3.6 道路幅員

- 藤沢版は PLATEAU の道路面から実測した（市域内 94.0%）。
- PLATEAU は **約300都市**（2025年度末の整備予定。国土交通省）。全国の市町村の一部である。
- → **PLATEAU の無い地域は、道路種別からの近似に落ちる**（藤沢版の市域外と同じ扱い）。
- ★藤沢市の PLATEAU には幅員属性（`uro:width`）が **0件** だった。他都市で入っているかは都市ごとに要確認。
- ★測っているのは**道路区域の幅（歩道・路肩込み）**であり、車道の幅ではない（継承）。

### 3.6.1 ★国土地理院ベクトルタイルで全国の幅員区分が取れる（2026-09-19 調査）

`docs/調査_API・MCP・既存プロジェクト.md` §1。国土地理院の最適化ベクトルタイル（試験公開・全国・3か月ごと更新）の
道路中心線に、**幅員区分**（3m未満／3m-5.5m未満／5.5m-13m未満／13m-19.5m未満／19.5m以上）が入っている。
→ **PLATEAU の無い地域でも、公式データで道幅の区分が取れる。** 上の「道路種別からの近似に落ちる」は解消できる見込み。
★ただし**一方通行と道路名は無い**ので、道路網そのものは OSM が要る。

### 3.7 アンダーパス（T-01）

- ★**全国化でいちばん素直に広がる部分。** 「自動車の道が橋と交差しているのにノードを共有していない
  ＝下をくぐっている」という幾何推定は、**OpenStreetMap だけで全国に適用できる。**
- 適合率 96.7% は藤沢での値。**他地域で同じ精度かは測っていない。**
- ★「水が溜まる形か」の判別は藤沢でもできなかった。全国版でも**区別せず判定不能**として扱う。
- ★**国土地理院ベクトルタイルにアンダーパスの手がかりが明示されている**（2026-09-19 調査）。
  地下道は道路の地物コード `2704`（トンネル）、高架下は交差する鉄道・道路の「橋・高架」と階層順（`vt_lvorder`）。
  藤沢の既知4か所で整合を確認した。OSM の幾何推定と**独立した第2の手がかり**として使える。

### 3.8 冠水注意箇所（実績）

- 藤沢版は関東地方整備局の公表分から、藤沢市域の13件に**手で座標を付けた**。
- 全国では地方整備局等ごとに公表されている。**様式・座標の有無・件数は未確認**（NK-09）。
- 手作業での座標付けは全国分では現実的でない可能性が高い。

### 3.9 検証 ── 全国一律の「正解」が無い

- 藤沢版は、市の雨水出水浸水想定区域を正解データにして AUC を測った。
- ★**全国一律で使える正解データは無い。** 内水想定区域は一部の市町村にしか無いため。
- → **正解データのある地域で、地域ごとに測って地域別に報告する**（藤沢方式の横展開）。
- ★「**全国で◯%当たる**」とは言わない。測った地域の値だけを、その地域の値として示す。
- ★スライダの校正点（湛水深 D = 1.407m）は**藤沢市の想定図の面積に合わせた値**。
  他地域にそのまま使えるかは分からない（NK-10）。

|---|---|
| Cloudflare Pages（Free） | 20,000ファイル ／ 1ファイル 25 MiB（2026-09-05 更新）。全体容量の上限は記載なし |

## 5. リスクスコア・経路探索（藤沢版を継承）

藤沢版の定義をそのまま使う。

```
S_topo = √( exp(−Δh₁₀₀/d) · exp(−Δh₂₅₀/d) )      d = 1.0 m
cost(e) = t(e) × ( 1 + λ·risk(e) + μ·narrow(e) )
risk(e) = max( 0, S_topo − exp(−D) )             ※判定不能は 0（丸めない）
```

- ★Δh の計算は**その地域の平面直角座標系**で行う（§3.4）。
- ★λ の既定 8・μ の既定 0.5 は藤沢の実測で決めた値。他地域での妥当性は未確認。

## 6. 技術的な落とし穴（藤沢版 T-01〜T-19 の扱い）

|---|---|---|
