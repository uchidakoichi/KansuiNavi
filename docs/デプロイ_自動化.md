# デプロイの自動化（2026-10-06・利用者判断）

★**配信中（2026-10-07 初回）**: アプリ **https://kansui.pages.dev/** （Git 連携・master で自動）／
データ **https://kansui-data.pages.dev/data/** （`KANSUI_DATA_PROJECT=kansui-data tools/deploy-data.sh`）。
初回の確認: 外部参照にビーコン無し（T-24）・no-referrer・noindex・データ側 CORS `*`・区画は gzip・`roadKansuiCount` 4,289。
★ダッシュボードの新しい作成画面の「Continue with GitHub」は **Workers** を作る。Pages は画面下の「Pages に続行」から

★**アプリ本体と配布データを別の Cloudflare Pages プロジェクトにする。**
- アプリ本体（HTML・JS・Service Worker）… **GitHub の master へのプッシュで自動デプロイ**（Cloudflare の Git 連携でビルド）
- 配布データ（区画・index.json・places.json・road_kansui.json、約590MB）… **手元から手動デプロイ**（git に入れていないため）
- アプリはデータを `VITE_DATA_BASE`（ビルド時の環境変数）の場所から読む（`web/src/data-base.ts`）。データ側は CORS を許す（`web/tools/data-site/_headers`）

## 1. データのプロジェクト（初回だけ。★利用者の操作）

```bash
cd web
npx wrangler pages project create <データのプロジェクト名> --production-branch master
KANSUI_DATA_PROJECT=<データのプロジェクト名> tools/deploy-data.sh
```
- ★作ったら **Workers & Pages → プロジェクト → Metrics → Web 分析を無効**にし、もう一度 `deploy-data.sh`（藤沢版 T-24）
- 確かめる: `curl -sI https://<データのプロジェクト名>.pages.dev/data/index.json | grep -i access-control` → `access-control-allow-origin: *`

## 2. アプリのプロジェクト（初回だけ。★利用者の操作）

Cloudflare ダッシュボード → **Workers & Pages → 作成 → Pages → Git に接続**
1. GitHub の認可画面で Cloudflare Workers and Pages アプリを入れる。★**「Only select repositories」で `uchidakoichi/Kansui` だけ**を選ぶ（公式の推奨）
2. ビルドの設定
   | 項目 | 値 |
   |---|---|
   | 本番ブランチ | `master` |
   | ルートディレクトリ | `web` |
   | ビルドコマンド | `npm ci && npm run build` |
   | ビルド出力ディレクトリ | `dist` |
   | 環境変数 `VITE_DATA_BASE` | `https://<データのプロジェクト名>.pages.dev/data` |
   - Node の版は `web/.node-version` で固定している（公式: `.node-version` か `NODE_VERSION`）
3. 作ったら **Settings → Builds & deployments → Preview branch control を「None」**（`fujisawa` ブランチへのプッシュでビルドさせない）
4. ★**Metrics → Web 分析を無効**にし、再デプロイ（T-24）

## 3. ふだんの流れ

★**2026-10-11 から、公開リポジトリ `uchidakoichi/KansuiNavi`（MIT・履歴1コミットから。2026-10-11 に kansui-national から改名）が正。**
- `~/Developer/KansuiNational` の `origin` は**取得が公開リポジトリ、プッシュは公開と非公開 `Kansui` の両方**（`git remote -v`）
- Cloudflare Pages（kansui.pages.dev）は非公開 `Kansui` の master から、Render（kansui-national.onrender.com）は公開リポジトリの master からビルドする
- 非公開 `Kansui` の旧履歴（藤沢版から続くもの）はタグ `private-master-final`・`fujisawa-final` とブランチ `fujisawa` に残してある

- **アプリを直した** → `git push`（`~/Developer/KansuiNational` から）→ 自動でビルド・デプロイ
- **データを作り直した** → `web/public/sw.js` の `DATA_VERSION` を上げてコミット・プッシュ ＋ `tools/deploy-data.sh`
  - ★順番: **データを先に出してから**アプリをプッシュする（新しいアプリが古いデータを読む時間を短くする）

## 5. Render（2026-10-07 追加・利用者判断）

★**アプリ本体だけ**を Render の静的サイトとして配る。データは Cloudflare の kansui-data.pages.dev から読む（Render には置かない）。
設定はリポジトリ直下の **`render.yaml`**（Blueprint）。

1. ★利用者の操作: Render ダッシュボード → **New → Blueprint** → GitHub の `uchidakoichi/Kansui` を接続（GitHub の認可は**このリポジトリだけ**に絞る）
2. `render.yaml` が読まれ、`kansui-national` が作られる（rootDir `web`・`npm ci && npm run build`・`./dist`・`VITE_DATA_BASE`・ヘッダ）
3. 以後は master へのプッシュで Cloudflare と Render の**両方**が自動でデプロイされる

★Render の無料枠（https://render.com/docs/free 、2026-10-07 確認）:
- 静的サイトは無料。ただし**月の含まれる帯域・ビルド時間**から使う（含まれる量は、確認したページには書かれていなかった）
- 帯域を使い切ると、**支払い方法が無ければ無料のサービスがすべて止まる**。支払い方法があれば**超過分が請求される**
  → ★PoC 中は月額0円（全国版の方針）なので、**支払い方法を登録しない**か、使用量を Billing の Monthly Included Usage で見る
- ★Render は `_headers` を読まないので、ヘッダは `render.yaml` に同じ内容を書いた。**片方を変えたらもう片方も変える**

デプロイ後に確かめる（T-24 と同じ考え方。配信側が足すものを見る）:
```bash
curl -sL --compressed https://<サービス名>.onrender.com/ | grep -o 'https://[a-z0-9.]*' | sort -u
curl -sI https://<サービス名>.onrender.com/ | grep -iE 'referrer|robots|cache-control'
```
