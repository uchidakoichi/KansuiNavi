## 1. ★案B を棄却する（実測 2026-09-20）

### 1.1 何を見落としていたか

経路探索は、**最終的に選ばれた経路のリスクだけでは動かない。**
Dijkstra は「その道を選ばない」と決めるためにも、その道のコスト＝リスクを要る。
つまりブラウザが Δh を知っていなければならない範囲は、

- ❌ 最終経路 ＋ 250m　ではなく
- ✅ **探索で確定（settle）したノード全部 ＋ 250m**

である。★この差を勘定に入れていなかった。

### 1.2 実測

藤沢版の実グラフ（エッジ 177,542本）で、λ=8・閾値 0.2449 の Dijkstra を走らせ、
確定ノードの集合を記録した。そこから z15（DEM5A を叩くズーム）の必要タイル数を数えた。
タイル1枚の大きさは、藤沢版のキャッシュ 335枚の実測（**中央値 66KB** / p90 83KB）を使った。

| 距離帯 | n | 直線 km | 確定ノード | 経路ぶん | ★探索ぶん | 倍率 | ★転送量 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 短 | 20 | 2.1 | 9,272 | 7枚 | **31枚** | 4.4倍 | 2.0MB |
| 中 | 20 | 4.2 | 31,747 | 12枚 | **88枚** | 7.3倍 | 5.7MB |
| 長 | 20 | 8.8 | 97,832 | 20枚 | **216枚** | 10.8倍 | **14.0MB** |

全体: 探索ぶん 中央値 88枚（5.7MB）／ p90 227枚（14.6MB）／ 最大 289枚（18.6MB）。

★**比較の基準**: 藤沢市域＋3km を**まるごと**カバーする DEM5A は **335枚 = 21.6MB** しかない。
**長距離 1経路のために、市域全体の 65% を取ることになる。**

測定は `tools/measure_planB.py`。藤沢版の実グラフ・実タイルサイズを使う。

### 1.3 なぜ救えないか

| 救済案 | 効くか | 理由 |
|---|---|---|
| A* にして探索範囲を狭める | ★**部分的にしか効かない** | 現在の `router.worker.ts` は**素の Dijkstra**（A\* の実装は無い）ので、上の数字は実装どおりの値。A\* なら数倍は減らせるが、中距離でも数MBは残る。**1経路ごと**である点が変わらない |
| 必要になった時点で逐次取得（遅延読み込み） | ✗ | 枚数は同じ。直列になるぶん**遅くなる**だけ |
| 粗い DEM（DEM10B・z14）で探索し、経路だけ精密に | ✗ | **T-07**（DEM10B は Δh の分解能が不足）に正面から反する |
| 低い λ で一度引いてから精密化 | ✗ | 2回目の探索も同じだけ広がる。収束の保証も無い |

★加えて、**豪雨時＝アクセスが集中するとき**に、全利用者が1経路ごとに数MBの
標高タイルを国土地理院から取ることになる。絶対ルール3の精神にも反する。

### 1.4 結論

★**Δh は前処理で計算し、地域のグラフに載せて配る。**（＝案A に戻る）

前処理で出した `S_topo` をエッジごとに持たせる費用は **1バイト/エッジ**。
藤沢版のエッジ 177,542本なら **173KB**。実測した `graph.bin` は 1エッジあたり 26.1バイトなので、
**4%の増加にもならない。**

> **14MB の標高タイルを実行時に取る** vs **173KB を前処理で焼き込む。**

★残る本当の論点は「**前処理がその標高をどこから取るか**」であって、
「実行時に取るか」ではない。これは P-1 で測る。

## 2. 方針 ── 「県版を作る」のではなく「全国版を地域ごとに流す」

### 2.1 v0.1 の枠組みの何が悪かったか

v0.1 は「神奈川県パイロット」と書いていた。これだと**神奈川県専用のコードを書いて、
全国化のときに書き直す**ことになる。そうではなく、

> **パイプラインは最初から全国対応で書く。対象地域は引数。
> 神奈川県はその1回目の実行対象。**

| | v0.1「県版を作る」 | ★v0.2「全国版を地域ごとに流す」 |
|---|---|---|
| 捨てるコード | 全国化のときに書き直し | **ほぼ無い**（§3 で実測） |
| DEM キャッシュ | 地域ごとに作り直し | **積み上がる。同じタイルを二度取らない**（絶対ルール3） |
| 公開 | 県版として別に作る | **データが揃った地域から順に出せる** |
| 中断・再開 | — | ★**地域単位で再開可能**にする（全国は数日かかるため必須） |

### 2.2 それでも「まず1地域」にする理由

「いきなり全国」ではなく段階を踏む理由は、**規模が怖いから**ではない。次の3つである。

| # | 理由 | 神奈川県でないと得られないか |
|---|---|---|
| 1 | ★**分割の仕組みは1地域でも「本物」が要る。** 概算で県のグラフは約38MB で、Cloudflare Pages の **1ファイル 25 MiB を既に超える**（§4） | いいえ（どの県でも同じ） |
| 2 | ★**藤沢市が中に入る＝回帰テストになる。** 全国版のコードで藤沢を再計算し、藤沢版の数字（AUC 0.7197 / 幅員実測 94.0% / 適合率 96.7%）が再現するかを見られる | ★**はい。神奈川県だけ** |
| 3 | ★**標高の取得コストが非対称。** 神奈川県 約45分 に対し、全国は **約4.4日の連続取得**。設計を間違えれば国土地理院のサーバをもう一度4.4日叩くことになる | いいえ |

★理由2 が決め手である。**一般化の過程で静かに壊れる箇所は必ず出る**ので、
答えが分かっている場所が対象範囲の中にあることには替えがたい価値がある。

### 2.3 ★神奈川県だけでは足りない（v0.1 の弱点）

**神奈川県は、このアプリにとって日本でいちばん条件の良い県のひとつである。**

| 全国化の本当の難所 | 神奈川県で踏むか |
|---|---|
| 平面直角座標系が19系に分かれる | ❌ **IX系のみ。踏まない** |
| DEM5A の穴（山間部が T-07 で対象外になる） | ❌ ほぼ踏まない |
| 内水の正解データが無い（全国の大半がこれ） | ❌ 4市もある。踏まない |
| PLATEAU の無い地域（幅員が種別近似に落ちる） | ❌ 整備都市が複数ある |
| 道路密度が低い地域 | ❌ 全国有数に密 |

★**易しい道だけを通る検証は、誤った自信を与える。**
→ **地域2として「難所県」を1つ入れる。**

### 2.4 地域2（難所県）の選定条件

次を満たす県を1つ選ぶ。

- **複数の平面直角座標系にまたがる**（→ NK-08 が実地で測れる）
- **DEM5A に穴がある**（山間部を含む。→ T-07 が広範囲に効くとどう見えるか）
- **内水の想定区域も PLATEAU も無い市町村を含む**（→ F-12「この地域で何が使えるか」の表示を実地で試せる）

★**どの県がこれに当たるかは、平成14年国土交通省告示第9号（JGD2011 で EPSG:6669〜6687）の
適用区域を一次情報で確認してから決める。** 記憶で県名を挙げない（絶対ルール10）。
この確認は Phase 0 の机上作業として先に行う（§6）。

## 5. 測定項目

### P-1 標高の取得経路 ★地域1の最初にやる

**問い**: 1地域ぶんの DEM5A を、国土地理院に無理をかけずに取れるか。

| | 内容 |
|---|---|
| 方法 | 藤沢版の取得器（逐次・sleep 1.0秒・同時接続1・キャッシュ・UA 明示）をそのまま使う |
| 測る | 実タイル枚数 ／ 所要時間 ／ 転送量 ／ **DEM5A の被覆率**（NK-07 の地域版） |
| 見込み | 神奈川県 約2,700枚 × 1.0秒 ＝ **約45分** |
| ★全国への外挿 | ここで得た「km² あたりの枚数・秒数」から全国の所要を出す。**全国を実際には取らない** |
| ★地域2で必ず測り直す | 山間部を含む県で**被覆率がどう落ちるか**。ここが神奈川では分からない |

★**この結果で全国の取得方針（NK-05）が決まる。**
地域1で45分なら全国（約38万 km²）は単純計算で**約4.4日の連続取得**。
許容できないなら**基盤地図情報ダウンロードサービス**（利用者ご本人のログインが必要）へ
切り替える判断になる。★どちらを採るかはこの数字を見てから決める。

### P-2 地域分割と配信 ★この設計の山

**問い**: どの単位で切れば配信の上限に収まり、境界をまたぐ経路が引けるか。

| | 内容 |
|---|---|
| 分割の候補 | **2次メッシュ（約10km四方）** を第1候補。全国で番号体系が定義済みで、**県境・系の境界に依存しない** |
| 測る | 区画あたりのエッジ数・バイト数の分布（**最大**が 25 MiB に収まるか）／ 地域全体のファイル数（20,000 の上限に対して）／ 隣接区画を読んで経路が引けるか |
| ★境界をまたぐ経路 | 「必要な区画だけ読む」の**必要な範囲**をどう決めるか。★藤沢版は市域+3km を一度に読んでいたので**完全に新規** |
| 性能 | 区画をまたぐたびに待たされないか。★読み込み中に画面が固まらないこと |

★**藤沢版の自前配信フォントだけで既に 379ファイル使っている**ことを忘れない（上限 20,000）。

**合格判定**: ★**独自の閾値は置かない。** 25 MiB / 20,000ファイルという
**外から与えられた上限**に収まるかだけを見る。
（藤沢版で学んだとおり、根拠の無い閾値を発明すると合否が偶然で決まる。）

### P-4 国土地理院ベクトルタイルの幅員区分 ★今すぐ測れる

**問い**: 全国で取れる「幅員区分」は、実測幅員の代わりになるか。

★**地域1・2を待たずに、藤沢市の既存データだけで完結する。**
藤沢市には **PLATEAU から実測した幅員が市域エッジの 94.0%** にある。これを正解として、
`vt_rnkwidth`（3m未満／3m-5.5m／5.5m-13m／13m-19.5m／19.5m以上）と突き合わせる。

| | 内容 |
|---|---|
| 測る | 区分ごとの実測中央値が**単調に並ぶか**／ 区分の境界と実測値の食い違い／「その他・不明」の割合 |
| ★注意 | 測っているものが違う可能性がある。PLATEAU の実測は**道路区域の幅（歩道・路肩込み）**。地理院の区分が何を指すかは**仕様書で要確認** |
| ★使わないもの | `vt_width` は「地図表示用の仮想的な幅員」。実測ではない。**使わない** |
| 前提 | 最適化ベクトルタイルは**試験公開**で「URL やデータ構成、属性の有無や名称等が変わる可能性がある」と明記。★**必須要件の土台にしてよいかの判断材料**でもある |

### P-5 アンダーパスの幾何推定

**問い**: 適合率 96.7% は藤沢での値。他地域でも当たるか。

| | 内容 |
|---|---|
| 方法 | 地域全域に幾何推定（自動車 way が `bridge` の way と平面交差しつつノードを共有しない）を適用し、**無作為抽出した候補を目視で照合** |
| ★第2の手がかり | 国土地理院ベクトルタイルの地物コード `2704`（トンネル）と `vt_lvorder`（階層順）。**OSM と独立**なので一致・不一致を数えられる |

| 地域2で見ること | 都市部と山間部・農村部で適合率が違うか |

### P-6 地域別の検証（AUC）

**問い**: 藤沢以外でも S_topo は内水想定区域を予測できるか。

| | 内容 |
|---|---|

| ★スライダ校正 | D = 1.407m は**藤沢市の想定図の面積に合わせた値**。他市でも妥当かを見る（NK-10） |

| ★継承する落とし穴 | **T-13**（MapLibre の Worker はビルド出力に自動で入らない・**dev では再現しない**）／ **T-14**（`.gz` の二重展開・存在しないパスに 200 を返す配信）／ **T-15**（Service Worker にリダイレクト済み応答を持たせない）。★**必ず `npm run build` + preview で見る** |
| ★性能要件 | 藤沢版は「市域内の任意2点で3秒以内」。全国版は**距離で範囲を切る**必要がある（NK-06）。★この値は**測ってから**決める。先に置かない |

## 6. 順序と中止条件

```
Phase 0 ── データ待ち無しで今すぐ ─────────────────────
  P-4  幅員区分の答え合わせ（藤沢の既存データだけ）
  P-3a 告示の確認 → 地域→系の引き当て → ★地域2の選定
  ★全国対応への引数化（§3。19ファイル/66行＋新規4点）

Phase 1 ── 地域1: 神奈川県 ────────────────────────
  P-1 標高取得(約45分) → P-2 分割 ★山 → P-5 → P-6 → P-7
  ★藤沢市の回帰テスト（藤沢版と同じ数字が出るか）

Phase 2 ── 地域2: 難所県 ─────────────────────────
  P-3b 座標系の境界（実地） / P-8 F-12 の表示
  P-1・P-5・P-6 を測り直す（被覆率・適合率・正解データ不在）
```

- **Phase 0 は地域のデータを1バイトも取らずに進む。** 承認をいただければすぐ始められる。
- **P-2 がこの設計の山。** 「必要な区画だけ読む」は藤沢版に無い新規実装である。
- ★**各項目の終わりで止めて報告する**（作業の進め方のルール）。

## 7. ★この2地域でも測れないこと

正直に並べておく。

- **全国の DEM5A 被覆率**（NK-07）── 2県の値しか出ない
- **19系すべての組み合わせ** ── 地域2で境界を1か所見るだけ
- **長距離（複数県をまたぐ）経路** ── 地域内で閉じる
- **内水の正解データが無い地域での当たり具合** ── 原理的に測れない。★全国の大半がこの状態
- **実利用者の負荷** ── PoC を出るまで分からない
- ★**dip / flat の水準判定** ── 藤沢で識別できなかったものが他県で識別できる理由は無い
