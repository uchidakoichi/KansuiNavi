# 調査: 大量ダウンロードを避ける手段（API・MCP・既存プロジェクト）

| 項目 | 内容 |
|---|---|
| 調査日 | 2026年9月19日 |
| 依頼 | 「データをダウンロードすると巨大なので、API や MCP があれば使いたい。その前に GitHub に有用なプロジェクト・API・MCP があるか確認したい」 |
| 情報源 | 公式リポジトリ（`gsi-cyberjapan` / `Project-PLATEAU`）、公式サイト、実データ。民間の解説記事は使っていない |

---

## 0. 結論

1. **すべてを API で済ませることはできない。** ただし**大きな一括ダウンロードの大半は避けられる。**
   避けられない一括ダウンロードは **OpenStreetMap 日本（2.4 GB）の1回だけ**になる見込み。
2. ★**国土地理院の最適化ベクトルタイルに、全国の道路の「幅員区分」が入っていた。**
   PLATEAU（約300都市）に限られていた道幅の問題が、全国で解ける。
3. ★**同じタイルに、アンダーパスの手がかり（トンネル・橋・高架・上下関係）が明示されていた。**
   藤沢版では OSM から「形で推定する」しかなかった部分である。
4. ★**ただし一方通行と道路名が無い。** 車の経路探索には OSM が引き続き要る。
5. **MCP は開発中に AI が使う道具で、利用者のブラウザでは動かない。**
   アプリが配るデータ量は減らない。PLATEAU 公式の Agent Skills が使える。
6. ★**実行時に第三者 API を呼ぶ設計は採らない。** 豪雨時の集中で止まる／位置情報が渡る（草案 §1.3）。

## 1. 国土地理院 最適化ベクトルタイル（`optimal_bvmap`） ★最重要

| 項目 | 内容 |
|---|---|
| リポジトリ | https://github.com/gsi-cyberjapan/optimal_bvmap （公式。2026-09-18 更新） |
| 配信 | `https://cyberjapandata.gsi.go.jp/xyz/optimal_bvmap-v1/{z}/{x}/{y}.pbf`（地理院タイルと同じ方式）／PMTiles 1ファイル |
| 範囲・更新 | **全国**。3か月ごとに更新（最新 2026-09-17、2026年7月1日時点のデータ） |
| ズーム | 4〜16（z17 の情報は z16 に含む）。★ラスタの地理院タイルより数値が1小さい |
| 利用条件 | 国土地理院コンテンツ利用規約に従う。出典「国土地理院最適化ベクトルタイル」 |
| ★注意 | **試験公開。**「URL やデータ構成、データの内容（属性の有無や名称等）が変わる可能性があります」。基本測量成果ではない |

### 1.1 道路中心線（`RdCL`）の属性（公式仕様書 令和7年11月21日更新）

| 属性 | 内容 | 使いみち |
|---|---|---|
| `vt_rnkwidth` | **幅員区分**: 3m未満／3m-5.5m未満／5.5m-13m未満／13m-19.5m未満／19.5m以上／その他／不明 | ★全国の道幅（広い道の優先・消防車の観点） |
| `vt_rdctg` | 道路種別: 国道／都道府県道／市区町村道／高速自動車国道等 など | 道路種別の近似の置き換え |
| `vt_lvorder` | **階層順** 0〜4 | ★立体交差の上下関係 |
| `vt_code` | 地物種別コード（下表） | ★トンネル・橋の判定 |
| `vt_motorway` / `vt_tollsect` | 高速道路か／有料か | 経路の除外条件 |
| `vt_width` | ★**「地図表示用の仮想的な幅員」**。実測ではない | **使わない** |
| 一方通行・進行方向 | ★**記載なし** | → OSM が要る |
| 道路名 | ★**記載なし** | → OSM が要る（F-08 の地点名） |

地物種別コード（公式の地物コード表より。★表の抽出が崩れたため並びからの読み取り）:

| コード | 内容 |
|---|---|
| 2701 | 道路中心線・通常部 |
| 2703 | 道路中心線・**橋・高架** |
| 2704 | 道路中心線・**トンネル** |
| 2711〜2714 | ２条道路中心線（上下線が分かれた道）の通常部／雪覆い／橋・高架／トンネル |

### 1.2 ★藤沢の既知アンダーパスで実データを確かめた

z16 のタイルを4枚だけ取得（逐次・1秒間隔・UA 明示）。

| 既知の箇所 | 道路側 | 上を通るもの | 読み取れること |
|---|---|---|---|
| 湘南辻堂地下道（地下道） | `2704` トンネル | — | 道路そのものに印がある |
| 土棚石川線湘南台第一地下道（地下道） | `2704` トンネル | 鉄道は通常部 | 同上 |
| 高倉小田急アンダー（アンダーパス） | `2701` 通常部 | 鉄道 **`橋・高架`・階層順 1** | 上の鉄道で分かる |

## 2. OpenStreetMap 日本

| 項目 | 内容（Geofabrik、2026-09-19 確認） |
|---|---|
| 全国 | `japan-latest.osm.pbf` **2.4 GB** |
| 地方別 | 関東 483 MB ／ 関西 335 MB ／ 九州 299 MB ／ 東北 294 MB ほか（中部・中国・北海道・四国） |
| 更新 | 毎日（2026-09-18T20:21Z までのデータ） |
| ライセンス | **ODbL 1.0** |

- ★**一方通行・道路のつながり・道路名は OSM にしか無い。** 車の経路探索には必要。
- 2.4 GB は**1回の HTTP ダウンロード**で、標高タイル数十万枚（数日）とは性質が違う。地方別に分けて処理もできる。
- ★道路網を OSM から作る限り、**配布するグラフは ODbL の Derivative Database に当たりうる**（NK-11 は残る）。
  地理院の幅員区分を載せても、グラフ自体が OSM 由来である点は変わらない。

## 4. ハザード情報

| 手段 | 一括DL | 実行時 | 備考 |
|---|---|---|---|
| 重ねるハザードマップのタイル（洪水・高潮・内水） | 不要 | ○ | 藤沢版と同じ。★内水は一部市町村のみ |
| 不動産情報ライブラリ 防災情報 API | 不要 | ★× | 洪水浸水想定区域（想定最大規模）・土砂災害警戒区域・津波・高潮・指定緊急避難場所。PBF／GeoJSON。★**利用申請が必要**（審査5営業日目安）。API キーが要る |

★不動産情報ライブラリを**実行時に**使わない理由:
- API キーをブラウザに置くと露出する。隠すにはサーバ（中継）が要り、「サーバを持たない」に反する
  （実際、`geolonia/mlit-estate-library-proxy-api` は MapLibre で使うための中継 API として作られている）
- 豪雨時の集中で回数制限に当たりうる（草案 §1.3）
- → **前処理でのみ**使う候補。利用規約（取得データの再配布）の本文は**未確認**。

## 5. PLATEAU

| 手段 | 内容 |
|---|---|
| PLATEAU 配信サービス | **無償**。3D Tiles／MVT／地形／オルソ。データカタログ API あり。ドキュメントは https://docs.plateauview.mlit.go.jp に移行 |
| ★PLATEAU Agent Skills | `Project-PLATEAU/skills`（公式・MIT）。`plateau-api` スキルで、**AI コーディングエージェント（Claude Code 等）から配信サービスの REST／GraphQL API を使える**。`gh skill install Project-PLATEAU/skills plateau-api --agent claude-code --scope user` |

- 藤沢版は市の CityGML の ZIP（736 MB）から HTTP Range で必要部分だけ取った。
  全国では**データカタログ API で都市ごとの URL を引ける**ので、約300都市の ZIP を手で探さずに済む。
- ★道幅は §1 の地理院ベクトルタイルで全国分が取れるので、PLATEAU の道路面は**補助**（区分ではなく実寸が欲しい都市だけ）に下がる。

## 6. MCP について

★**MCP（と Agent Skills）は、開発中に AI が使う道具である。** 利用者のブラウザでは動かない。
アプリが配るデータの量も、前処理で扱うデータの量も、それ自体では減らない。

| 見つかったもの | 中身 | 評価 |
|---|---|---|
| ★PLATEAU Agent Skills（公式） | 配信サービスの API | **使える**。開発中の PLATEAU 取得が楽になる |
| `jagan-shanmugam/open-streetmap-mcp`（★224・MIT）ほか OSM 系 | 公開 Nominatim／Overpass／OSRM を呼ぶ | ★大量取得には使えない（公開サーバの利用方針）。開発中の少量の確認向け |
| `koizumikento/reinfolib-mcp`（★2・MIT・非公式） | 不動産情報ライブラリ API | 前処理で使うなら候補。非公式 |
| `mahdin75/gis-mcp`（★193・MIT） | 一般的な GIS 演算 | 手元の Python で足りている |
| 国土地理院・ハザードマップ専用の MCP | **見つからず** | — |

## 7. 使わないほうがよいもの

| 手段 | 理由 |
|---|---|
| 実行時の経路探索 API（OSRM 公開サーバ等） | ①出発地・目的地が第三者へ渡る（ルール6） ②**自前のリスク重み（Δh・幅員）を渡せない** ③豪雨時に止まる |
| 実行時の住所検索 API | ①入力した住所が第三者へ渡る ②豪雨時に止まる。藤沢版も同梱方式を選んだ |
| 地理院 標高 API（`getelevation.php`） | 絶対ルール2 |

## 8. 設計への影響（提案。★決定ではない）

見つかったものを組み合わせると、**一括ダウンロードを OSM の 2.4 GB だけにできる**。

| 部品 | 取り方 |
|---|---|
| 道路網・一方通行・道路名 | OSM 日本（前処理・1回） |
| 幅員区分・トンネル・橋・上下関係 | ★地理院ベクトルタイル（前処理で OSM の道に載せる） |
| 標高・Δh | ★**案B を採用（2026-09-20）**。実行時にブラウザが必要範囲の標高タイルだけ取って Δh を計算（一括DL不要）。案A（前処理で数日かけて取得）は不採用 |
| ハザード（重ねて表示） | 実行時に重ねるハザードマップのタイル（藤沢版と同じ） |

案B の論点（パイロットで測る）:
- 1経路あたり何枚の標高タイルを取るか（通信量・速さ）
- 豪雨時に全利用者が地理院の標高タイルを取ることの負荷（地図タイルはすでにそうしている）
- ブラウザでの Δh 計算時間（半径 250m の最小値フィルタ）
