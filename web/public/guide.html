冠水回避ルート検索（全国版・実証実験）

このアプリの考え方と計算方法

大雨で水がたまりやすそうな道を地形から推定し、そこをなるべく通らない道を出すアプリです。 このページでは、何を根拠に線を引いているのか、どこまで信用できるのかを、計算しているとおりに説明します。

先に読んでください

  • これは実証実験のアプリです。国・自治体の公式な避難誘導や、通行できるかどうかの判断を行うものではありません。
  • 出てくるのは「安全な経路」ではなく、静的なデータ上、相対的にリスクが低いと推定される経路です。
  • いま降っている雨や、通行止め・工事・事故の情報は入っていません。地形と公表データだけで計算しています。
  • 色がついていない道にも、水がたまることはあります。「表示がない＝安全」ではありません。
  • 通るかどうかの最終判断は、必ず現地の状況を見てご自身で行ってください。

冠水した道路には、絶対に進入しないでください。

地図の線の見方

色は「危険度の順番」ではなく、何を根拠にそう言っているかで分けています。根拠の違うものを混ぜないためです。

黄〜赤の線 ／ 地形からの推定

まわりより低く、水が集まりやすそうな道（「雨の強さ」の閾値を超えた区間）。赤に近いほど、まわりとの高低差が小さい（より低い）ことを表します。実際に水がたまった記録ではありません。
★経路を引いたときに読み込んだ範囲（経路の周り数km）だけに薄く重ねます。全国を一度には読み込めないため、経路を引く前や、読み込んでいない場所には出ません。

青い線（太い） ／ 提案する経路

リスクをなるべく避けるように計算した道。経路の上でも、点灯している区間は黄〜赤、判定不能は濃い灰色で描きます。既定では点灯区間を避けるので、ほとんど青になります。色の付いた区間を見たいときは「リスクをどれだけ避けるか」を 0 にすると、最短の道で点灯区間がそのまま出ます。

濃い灰色の線 ／ 判定不能

アンダーパス・高架下など、地形からは危険とも安全とも判定できない区間。4段階の色には混ぜません（理由）。

赤紫の点 ／ 冠水想定箇所（位置を確かめられたもの）

国の公表データにある箇所。経路の計算では最もリスクの高い区間として扱います。経路が通ると赤紫で描きます。

赤紫の破線の円 ／ 冠水想定箇所（位置は未確認）

円のどこかにあると推定したもの。経路の計算には使っていません。押すと元の資料と確かめ方が出ます。
★説明は円の中心の白い丸を押すと開きます。円の中のほかの場所は、ふつうに出発地・目的地として押せます。

灰色の破線 ／ 最速の経路（比較用）

リスクを一切考えずに、いちばん早く着く経路。提案した経路との差が、迂回の「代金」です。

考え方 ― 「低い場所」ではなく「まわりより低い場所」

標高が低いことと、水がたまることは別ものです。海沿いの平地は標高が低くても、水は海へ抜けていきます。 逆に、高台の中のくぼ地には水がたまります。冠水の条件は「まわりより低い（水が集まる）」＋「抜けない（排水が追いつかない）」なので、 中心の指標は絶対標高ではなく、近くのいちばん低い所との差にしています。

Δh(p) = h(p) − min{ h(q) | q ∈ N(p, r) }
p評価する地点（道路の上の点）
h標高［m］
N(p, r)p を中心とする半径 r の円の中
r100m と 250m の2つを併用

Δh ≈ 0 なら、半径 r の中でそこが最も低い＝くぼ地の底です。Δh が大きいほど、まわりより高い＝相対的にリスクが低いと読みます。 2つの半径を使うのは、100m だけだと道路の細かな凹凸を拾い、250m だけだと小さなくぼ地を見落とすためです。

使っている標高データ

出所国土地理院の標高タイル。5mメッシュ（DEM5A・5B・5C）を優先し、画素ごとに精度の高い順で埋めます
10mメッシュ5mメッシュが整備されていない所（北海道・東北・奄美・沖縄の一部など）は DEM10B（誤差の目安 5m）で推定します。その区間は注意地点の一覧に「精度の低い10mメッシュの標高からの推定」と出し、標高プロファイルでは細かい点線で示します。数 m のくぼみは誤差に埋もれることがあります
水面5mメッシュは川や池の水面を「欠損」にしています。そこを10mメッシュで埋めると水面の高さで結果が変わるので、水域（地理院の水域データ）の画素は埋めません
精度5mメッシュの標高精度は標準偏差 0.3〜1.4m。数cmの差を意味のあるものとして扱っていません
欠損データの無い画素を「標高0m」と読まない。0m と読むと、水部が「最も低い＝最も危険」になってしまうためです。どの種類でも無ければ「標高不明」のままにし、その区間は判定不能になります
距離距離の計算は、地域ごとの平面直角座標系（全国19系）で行います。ウェブ地図の座標のまま測ると、北緯35度で約1.2倍の誤差が出るためです

道路への割り当て

道路データ（OpenStreetMap）の中心線を 20m おきに区切って Δh を求め、1本の道（区間）にまとめるときは 平均ではなく最大値（最も危ない点）を採ります。

1点でも危ないくぼみがあれば、その道は危ないからです。平均を採ると、長い道の中の1か所のくぼ地が薄まって消えてしまいます。

地形スコアの計算

S_topo = √( exp(−Δh₁₀₀ / d) · exp(−Δh₂₅₀ / d) ) = exp( −(Δh₁₀₀ + Δh₂₅₀) / 2d ) d = 1.0 m

値は 0〜1。1 に近いほど「まわりより低い」ことを表します。

なぜ2つを掛けて平方根を取るのか（幾何平均）。指数の中が足し算になるので、d の値を変えても道の順位が変わりません。 表示の目盛りを変えても予測の良さが動かない、という性質が必要だからです。
なぜ大きい方・小さい方の一方だけを使わないのか。定義上いつも Δh₂₅₀ ≧ Δh₁₀₀ なので、片方を採るともう片方のスケールが効かなくなります。
なぜ指数なのか。直線で頭打ちにすると、Δh が大きい側の順位が潰れます（藤沢で比べたところ、直線の頭打ちは予測の良さが明らかに劣りました）。

「雨の強さ」のつまみ

点灯する道: S_topo > exp(−D) D = つまみの値［m］

つまみを強くするほど D が大きくなり、色のつく道が増えます。 S_topo > exp(−D) は (Δh₁₀₀ + Δh₂₅₀) / 2 < D と同じ意味なので、 「まわりとの高低差が平均 D メートル未満の道を点灯させる」ということです。

校正点D = 1.407m。藤沢市の想定最大規模の雨（1時間153mm）の内水浸水想定区域と、点灯する範囲の面積が一致する位置です
★全国ではこの校正は藤沢市の図だけで行ったものです。他の地域で同じ意味になるかは測っていません
mm/h でない理由校正できる点が1つしかないためです。途中の数字を書くと根拠のない補間になり、天気予報の雨量と取り違えられます

「判定不能」とは

アンダーパス（線路や道路の下をくぐる道）は、大雨でいちばん水没しやすい場所です。 ところが標高データでは、その低さが見えません。

つまり、いちばん危ない場所が、データの上では「低い場所」として現れません。 そこで、そういう場所を「危険」でも「安全」でもなく「判定不能」として、4段階の色から外し、濃い灰色で示しています。 「わからない」を「大丈夫」に丸めない、という考え方です。

どうやって見つけているか

地図データ（OpenStreetMap）では、立体交差は「上の道を橋にする」か「下の道をトンネルにする」かのどちらか一方で表すのが正しい書き方です。 そのため、橋の下をくぐる道には印が付いていないのが普通です。 このアプリは、車の通る道が、橋（道路・鉄道）と交わっているのに地図上でつながっていない所を、交差の形から見つけています。

藤沢で空中写真と1か所ずつ見比べたところ、こうして見つけた120か所のうち116か所（96.7%）が本当に立体交差でした。他の地域で同じ精度かは測っていません。網羅も保証できません。

もう一つの判定不能 ― 標高データが無い区間

標高データが無い区間も、地形からは判定できないので同じ扱いにしています。注意地点の一覧では「標高データが無い区間」と、理由を分けて出します。

判定不能の場所を通りたくないときは、「検出できたアンダーパスを除外する」にチェックを入れてください。 「リスクをどれだけ避けるか」のつまみでは避けられません（理由）。

冠水想定箇所（公表データ）

国が「大雨で冠水するおそれがある」と公表している箇所です。地形からの推定ではなく公表された箇所なので、 雨の強さのつまみに関係なく表示し、経路の計算では最もリスクの高い区間として扱います。

地域位置の出所確かめ方
北海道・東北・北陸・中部・近畿・中国・四国・九州・沖縄 各地方整備局等の「道路防災情報Webマップ」が公表している座標 座標の市区町村が、その箇所の説明表（PDF）に書かれているか ／ 橋でない道路に 30m 以内で結び付くか
関東（東京・神奈川・千葉・茨城・栃木・山梨） 座標は公表されていないので、資料の地図の番号付きの印から、本アプリが位置を推定 資料の地図の印と、道路データの立体交差・トンネルの位置が一致するか
点上の確かめ方を通ったもの。経路の計算に使います
破線の円位置が確かめられないもの。表示だけで、経路の計算には使いません
一覧だけ位置を決められなかったもの。パネルの「冠水想定箇所」の一覧に、元の資料へのリンクと一緒に出します
未収録埼玉・群馬・長野（資料の地図から位置を十分に読み取れないため）

印を押すと、元の資料（PDF）の該当ページと、どこを見れば確かめられるかが出ます。 気になる箇所は、ご自身の目で資料と見比べてください。 ★確かめ方は機械で行っていて、AI（大規模言語モデル）の判断は使っていません。

掲載されていない場所でも冠水は起きます。通行の際は、現地の案内や規制情報に従ってください。

経路の計算

経路は、道ごとの「コスト」の合計が最も小さくなる道すじを、お使いの端末の中で計算しています（サーバには送りません）。

cost(e) = t(e) × ( 1 + λ·risk(e) + μ·narrow(e) )
t(e)その道の通過時間［秒］（道の種類と制限速度から）
risk(e)max( 0, S_topo − exp(−D) )。点灯した分だけ効きます。冠水想定箇所（点）は最大値
narrow(e)道の狭さ（0〜1）。国土地理院の幅員区分（3m未満／3〜5.5m／5.5〜13m／13〜19.5m／19.5m以上）から決めます
λ「リスクをどれだけ避けるか」。既定 8（0〜64 の15段）
μ「広い道を優先」。既定 0.5

リスクと道幅を別の項にしています。足し合わせて1つの値にすると、どちらの理由で遠回りしたのかを説明できなくなるためです。 地形からの推定（risk）と、災害時は狭い道が問題になりやすいという運用上の好み（narrow）は、根拠の性質が違います。
判定不能（アンダーパス）は risk = 0 として扱います。「わからない」を「危険」に丸めないためです。 そのため λ をいくら上げても判定不能は避けられず、避けるにはチェックボックスで除外します。 除外すると、位置を確かめられた冠水想定箇所も一緒に避けます。ただしほかに道が無いとき（出発地・目的地がアンダーパスの向こうにしか出られない場所など）は通り、その数を画面に出します。出発地・目的地を勝手に動かさないためです。
幅員は「区分」であって実測ではありません。「3m未満」の道が本当に何mかは分からないので、消防車が通れるかなどの判断には使えません。

広い道を優先★上げるほど幹線を通ります。幹線ほど立体交差の下を通るので、判定不能の通過が増えることがあります
長い経路直線 40km までは常に計算します。それより長い経路は、読み込む道路データの量が一定以下のとき（最大 112km）だけ計算します。端末の負担を抑えるためです
つながらない所出発地・目的地が、ほかとつながっていない小さな道路のかたまりにある場合は、近くのつながった道へ寄せて計算します

計算に入れていないもの

洪水・高潮の浸水想定区域入れていません。藤沢での比較で、洪水の想定だけでは地形からの推定より当たりが低く、また川の氾濫は、このアプリが最も使われる大雨の場面より一段上の局面だからです
内水の浸水想定区域入れていません。この図は推定が当たっているかを採点する「答え」に使っているためです。答えを見ながら答案を書けば、点数は上がっても実力は分かりません
いま降っている雨・通行止め入っていません。事前に見ておくためのアプリです
排水設備入っていません。標高データからは、排水管の太さも詰まりも見えません

どれくらい当たるか

地形スコアが、市の内水（雨水出水）浸水想定区域をどれだけ言い当てるかを、神奈川県の4市で測りました。 AUC は 0.5 が当てずっぽう、1.0 が完璧です。

市AUC（地形スコア）AUC（標高だけ）
横須賀市0.8720.831
綾瀬市0.8370.674
藤沢市0.7130.703
平塚市0.7000.720

地域によって当たり方が大きく違います（AUC 0.70〜0.87）。 「まわりより低い」で見るほうが「低い」で見るより当たる、という考え方も、4市のうち3市では成り立ち、平塚市では逆でした。 「全国で◯%当たる」とは言えません。測っていない地域の当たり方は分かりません。
原理的な上限があります。冠水は「水が集まる」と「抜けない」の両方で決まるのに、標高データからは前者しか見えません。

結果の読み方

最速との比較提案した経路と最速の経路の所要時間の差が、迂回の「代金」です。何が減って何が増えたかを並べて出します
注意地点の一覧経路上の注意すべき区間を、危ない順に選んで走る順に並べます。行を押すと地図がそこへ移ります。一覧に出ていない区間が安全という意味ではありません
標高プロファイル経路に沿った高さの変化。橋の上とトンネルの中は、標高データが橋の下の地面や上の山の地表を測るので、両端を結んだ破線で示します。細かい点線は10mメッシュの区間、線が切れている所は標高データが無い区間です（0m として描きません）
オフライン一度読み込んだ区画と地図は端末に残り、電波が無くても開いて経路を計算できます。ただし読んでいない区画へは経路を引けません

できること・できないこと

できること

  • 地形から「まわりより低い道」を全国について機械的に洗い出す
  • アンダーパスを、地図データの印に頼らず橋との交差の形から見つけて別扱いにする
  • 国が公表している冠水想定箇所を表示し、経路の計算に入れる
  • リスクを避けた経路と最速の経路を並べ、代金を数字で見せる
  • 電波が無くても、読み込み済みの範囲なら経路を計算する

できないこと

  • 当たり方は地域で大きく違い、中くらいの所もあります
  • 排水設備の能力が見えません
  • いま降っている雨、通行止め、工事、事故は反映していません
  • アンダーパスの見つけ方は、網羅を保証できません
  • 道幅は区分で、実際の幅（特に車が通れる幅）は分かりません
  • 自動車の経路だけです（徒歩・自転車は対象外）

「危険と出た＝必ず冠水する」でも「出ない＝安全」でもありません。地形だけで冠水を当てにいく方法には、原理的な上限があります。
